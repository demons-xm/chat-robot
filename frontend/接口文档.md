# 知答智能客服 Agent 前端接口文档

此文档描述 Vue 3 + TypeScript 前端如何调用 `backend` 中的客服 API。接口定义以当前后端 Pydantic Schema 和路由为准；字段采用 camelCase，所有请求和响应均为 JSON。

## 1. 开发与连接

```powershell
cd frontend
npm install
npm run dev
```

后端默认启动地址为 `http://127.0.0.1:8000`，前端默认 API Base URL 为：

```text
http://127.0.0.1:8000/api/v1
```

在工作台右上角打开「连接设置」，配置：

| 配置 | 说明 |
| --- | --- |
| 后端 API Base URL | API 版本根路径，包含 `/api/v1` |
| JWT Bearer Token | 由认证系统签发的 JWT。主问答接口必填 |
| 用户 ID | 对话用户标识；必须与 JWT 的 `userId`、`user_id` 或 `sub` 声明一致 |
| 租户 ID | 隔离会话与知识库，例如 `tenant01` |

连接设置保存在当前浏览器 `localStorage`。除请求头 `Authorization` 外，不会将 Token 放入 API 请求体。页面不提供注册、登录或 Token 签发接口。

### 统一响应

```ts
interface ApiResponse<T> {
  code: number
  message: string
  data: T
  requestId: string
}
```

`code === 200` 表示成功。常见 HTTP/业务状态码：`400` 参数错误、`401` 鉴权失败、`404` 资源不存在、`429` 限流、`500` 服务内部错误，以及主问答超时的 `504`、模型不可用的 `503`。错误响应同样携带 `code`、`message` 和 `requestId`。

所有受限请求均受来源 IP / 租户限流影响。遇到 `429` 时，客户端应提示稍后重试；勿自动高频重试。

## 2. 通用 TypeScript 调用

项目已在 `src/services/api.ts` 中封装 `AgentApi` 和错误处理：

```ts
import { AgentApi, ApiError } from '@/services/api'

const api = new AgentApi({
  baseUrl: 'http://127.0.0.1:8000/api/v1',
  token: '<JWT>',
  userId: 'u-001',
  tenantId: 'tenant01',
})

try {
  const result = await api.chat({
    sessionId: 'sess-123',
    query: '我的订单什么时候发货？',
    extraEntity: { orderNo: 'OD20261016001' },
  })
  console.log(result.answer, result.referenceDocs)
} catch (error) {
  if (error instanceof ApiError) {
    console.error(error.status, error.message, error.requestId)
  }
}
```

## 3. 接口清单

请求方法均为 `POST`。除 `/agent/chat` 外，当前后端这些 API 不要求 JWT；后端会从请求体中的 `tenantId` 执行租户范围过滤/存取。生产部署应在 API 网关或后端增加适用的访问控制策略。

| 接口 | 鉴权 | 用途 |
| --- | --- | --- |
| `/agent/chat` | Bearer JWT | 完整客服问答入口 |
| `/intent/classify` | 无 | 独立意图识别 |
| `/rag/retrieve` | 无 | 知识库检索 |
| `/agent/router` | 无 | Agent 路由测试 |
| `/memory/get` | 无 | 读取三级记忆 |
| `/memory/save` | 无 | 异步保存记忆 |
| `/eval/llmjudge` | 无 | 单条 LLM 评测 |
| `/eval/batch` | 无 | 批量回归评测 |

### 3.1 主问答

`POST /agent/chat` — 请求头：`Authorization: Bearer <JWT>`。

```ts
interface ChatRequest {
  sessionId: string
  userId: string
  query: string
  tenantId: string
  channel?: string
  extraEntity?: Record<string, unknown>
  timeout?: number // ms，100–120000；默认由后端配置决定
}

interface ChatResult {
  answer: string
  intentInfo: IntentInfo
  agentName: string
  referenceDocs: ReferenceDocument[]
  queryUnderstanding: QueryUnderstanding
  transferHuman: boolean
  transferReason: string
  sessionSummary: string
}

interface QueryUnderstanding {
  originalQuery: string
  rewrittenQuery: string
  rewriteConsistent: boolean
  queryType: 'general_knowledge' | 'personal_order_status' | 'other'
  requiredSlots: string[]
  missingSlots: string[]
}
```

- `sessionId` 在一段多轮会话中保持不变；创建新会话时生成新的 ID。
- `userId` 必须和 JWT 身份一致，`tenantId` 决定知识库和记忆隔离边界。
- 后端结合近期会话上下文理解省略表达，并可使用 LLM 生成独立检索查询；改写必须通过独立的语义一致性校验。校验失败或服务不可用时，`rewrittenQuery` 回退为 `originalQuery`。知识检索会同时使用原问题和已验证改写。
- `queryUnderstanding.queryType` 区分一般知识问答与个人订单实时状态查询；`requiredSlots`/`missingSlots` 表示理解出的必要信息。当前后端尚未接入订单/物流实时查询服务，因此个人订单状态问题会明确说明能力边界，不会因缺少订单号反复追问或编造物流状态。
- 只有当前问题明确请求人工服务时，后端才返回人工转接建议；低置信度本身不会触发转人工。该建议也不代表已实际呼叫人工坐席。
- 后端当前默认超时配置为 8 秒。前端如提交更长 `timeout`，须确保网关/反向代理超时也允许该请求时长。
- 评测和记忆写入在后台执行，不应由前端重复触发以模拟主问答的副作用。

### 3.2 意图识别

`POST /intent/classify`

```ts
interface IntentRequest {
  query: string
  tenantId: string
  sessionId?: string // 有值时后端读取该会话近期工作记忆
}

interface IntentResult {
  intentLabel: string
  confidence: number // 0–1
  subIntent?: string
  hitKeywords?: string[]
  scoreDetail?: {
    llmFewShotScore: number
    embeddingScore: number
    regexKeywordScore: number
  }
  needConfirm?: boolean
  transferHuman?: boolean
}
```

当前内置意图包含配送咨询和身份咨询。“支持哪些快递/承运商”等明确配送方式问题会优先识别为配送咨询；“你是谁/你能做什么”等问题会优先识别为身份咨询。用户当前明确提出转人工请求时才会设置 `transferHuman: true`；单纯提到真人/客服或分类置信度较低不会自动触发转人工。

### 3.3 RAG 检索

`POST /rag/retrieve`

```ts
interface RagRetrieveRequest {
  query: string
  tenantId: string
  topK?: number // 1–20，默认 3
  enableQueryRewrite?: boolean // 默认 true
}

interface RagRetrieveResult {
  rewriteQueries: string[]
  rawRetrieveList: ReferenceDocument[]
  rerankDocs: ReferenceDocument[]
  mrr: number | null
}

interface ReferenceDocument {
  docId: string
  content: string
  score?: number
}
```

`mrr` 在没有带相关性标注的评测数据时为 `null`。它不是单条检索文档的相关度分数。

### 3.4 Agent 路由

`POST /agent/router`

```ts
interface AgentRouteRequest {
  intentLabel: string
  entity?: Record<string, unknown>
  tenantId: string
  query?: string
}

interface AgentRouteResult {
  targetAgent: string
  routeReason: string
  fallback: boolean
}
```

路由按后端规则结合实体、意图和关键词决策。示例：

```json
{
  "intentLabel": "订单咨询",
  "entity": { "orderNo": "OD123456" },
  "tenantId": "tenant01",
  "query": "查一下这个订单"
}
```

### 3.5 三级记忆

`POST /memory/get`

```ts
interface MemoryKeyRequest {
  sessionId: string
  userId: string
  tenantId: string
}

interface MemoryResult {
  workingMemory: Array<{ role: string; content: string }>
  episodicMemory: string[]
  userProfile: Record<string, unknown>
}
```

`POST /memory/save`

```ts
interface MemorySaveRequest extends MemoryKeyRequest {
  query: string
  answer: string
  sessionSummary?: string
  userFeatures?: Record<string, unknown> | string[]
}

interface MemorySaveResult {
  queued: boolean
}
```

`/memory/save` 返回 `queued: true` 代表任务已入后台线程池，不表示向量存储已完成。主对话链路已经自动保存该轮工作记忆与摘要，通常只在独立记忆管理场景调用此接口。

### 3.6 LLM-as-Judge 评测

`POST /eval/llmjudge`

```ts
interface JudgeRequest {
  query: string
  answer: string
  reference?: string
}

interface JudgeResult {
  evaluationId: string
  score: {
    relevance: number
    accuracy: number
    completeness: number
    usefulness: number
  }
  avgScore: number
  judgeReason: string
  qualityTag: '优质' | '一般' | '不合格'
}
```

成功的评测结果会写入后端本地 SQLite 评测库。模型未配置或不可用时返回错误，不应将此情形显示为有效评分。

### 3.7 批量回归评测

`POST /eval/batch`

```ts
interface BatchJudgeRequest {
  samples: Array<JudgeRequest & { sampleId?: string }> // 1–100
}

interface BatchJudgeResult {
  total: number
  completed: number
  failed: number
  avgScore: number | null
  results: Array<JudgeResult & { sampleId?: string; error?: string }>
}
```

单个样本失败会在 `results` 对应项返回 `error`，批量任务继续处理其他样本；整体 HTTP 请求仍可成功。前端应同时呈现完成、失败数量及有效样本平均分。

## 4. 前端模块

| 路径 | 说明 |
| --- | --- |
| `src/types/api.ts` | API 请求、响应 TypeScript 类型 |
| `src/services/api.ts` | Base URL、统一 JSON 请求、JWT 头和错误处理 |
| `src/App.vue` | 对话工作台、模块调试、质量评测与连接设置 |
| `src/assets/main.css` | 布局、组件样式与响应式断点 |
| `index.html` | 中文页面语言、标题和描述 |

所有 API 都通过 `AgentApi` 调用；页面组件不直接拼接 `fetch` 请求。新增接口时先在 `src/types/api.ts` 定义请求/响应类型，再在 `src/services/api.ts` 扩展 API 方法和页面视图。
